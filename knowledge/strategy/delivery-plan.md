# Delivery Plan

The current implementation order is in [the issue backlog](implementation-backlog.md)
and [GitHub tracker #119](https://github.com/code-with-rashid/agentic-arena/issues/119).
This replaces the earlier plan that put Boundary Response first.

## Stage 1: navigation and conceptual foundations

Issues #108–#110 establish shared knowledge, user-problem navigation, and neutral
architecture explanations. Exit gate: a visitor can identify their problem and
follow a route to concepts and evidence without choosing one framework first.

## Stage 2: implement and diagnose

Issues #111–#112 add the executable loop and problem register. Exit gate: the
example works offline, deliberate failures are detected, and problems link to
reproducible evidence.

## Stage 3: essential harness capabilities

Issues #113–#116 cover context, protocols, reliability, and evaluation. Exit gate:
examples establish explicit contracts and limits. Independent observations must
be verified before broader comparisons.

## Stage 4: boundaries and operations

Issue #107 applies the foundations to policy denial. Issue #117 adds execution,
security, and operations guidance. Exit gate: actual fixture effects are observed,
allowed work is preserved, and simulation is distinguished from isolation.

## Stage 5: synthesize and expand

Issue #118 produces requirements and experiments for a separate future harness.
Continue [research](../research/backlog.md) across interaction, skills supply chain,
local inference, optimization/training, advanced memory, and distributed operations.

## Maintenance and neutrality

Update shared knowledge and evidence in implementation PRs. Keep
[personal learning](../personal/README.md) separately. The future harness receives
the same comparison conditions as other implementations.

No calendar or automatic monitoring is implied. GitHub issues own current status;
acceptance gates determine progression. See [the agreed learning path](concept-first-path.md).
